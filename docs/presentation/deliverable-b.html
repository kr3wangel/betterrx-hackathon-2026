B Deliverable B · AI approach

One model, in the one place rules structurally cannot go.

We use Claude in exactly one spot: reading a vendor's free-text reply into a structured order event. The rules baseline — /yes|confirm/ → accept, datetime regexes — fails on a whole category of input: order inference and relative-time resolution. Everything else is deterministic on purpose.

The safety story is one gate

The parse is schema-constrained, so the model can't invent fields or patient details. Then a confidence gate decides whether it ever touches an order — with a human on the other side of it.

Even an auto-applied parse can only fire a valid transition — a hallucinated "delivered" on an order still in ordered is rejected with a 409 and falls to review. With no API key, the whole pipeline degrades to the queue rather than guessing.

Where the model earns its place — and where we refused to spend it

The same judgment as the rules-based risk engine, applied inside the AI choice: match the tool to the task.

AI, because rules can't represent it
  • Open-vocabulary vendor prose — every new vendor is a new dialect; a model handles the long tail natively.
  • Order inference — resolving which open order an unreferenced reply is about.
  • Relative-time resolution — "Thursday by 10" → a real deadline the risk engine can act on.
Deterministic, because rules win
  • Risk scoring — a rules engine, so every score is a sentence a case manager can argue with.
  • Reply-code addressing — a bare "7" routes to the right order by arithmetic, no inference.
  • Caregiver rating — a digit is a digit; regex, no model.
  • The magic-link tap — confidence 1.0, no model in the path of a state change.

Model choice: deliberately small. Cost: measured, not estimated.

It runs on Haiku 4.5 because the task is extraction, not reasoning — a bigger model adds latency and cost without adding accuracy here.

The rules, backtested honestly

On synthetic data — and we say so Synthetic

npm run backtest replays every seeded order tick by tick exactly as the watchdog would have seen it — state rebuilt from the event ledger, a flag only counts if it fired before the deadline. Against the shipped threshold of 70, the risk engine flagged 78% of late deliveries a median 8.7 hours early, with false alarms on 27% of on-time orders (n=203). We keep the false-alarm rate in the open — most of those flags were reasonable when they fired. This demonstrates the approach — explainable rules over per-vendor × equipment × weekday history — not field performance, because there is no public DME delivery-timing dataset. Re-run after reseeding: numbers move with the seed date.
